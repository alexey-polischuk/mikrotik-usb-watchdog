# USB Watchdog для LTE/3G модема — MikroTik RB2011 (RouterOS 7.24)

Скрипт автоматического мониторинга и восстановления интернет-соединения через USB-модем для роутеров MikroTik (протестировано на **RB2011** с **RouterOS 7.24**).

---

## Возможности и логика работы

1. **Периодическая проверка (Watchdog):**
   - Каждые 30 секунд скрипт отправляет ICMP-пинг на контрольный узел (по умолчанию `77.88.8.8` — Яндекс DNS).
   - Для исключения ложных срабатываний при случайных единичных потерях пакетов, падение фиксируется после `failThreshold` неудачных проверок подряд (по умолчанию 4 проверки = 2 минуты).

2. **Быстрые попытки сброса (USB Power-Reset):**
   - При фиксации аварии скрипт передергивает питание USB-порта (`/system routerboard usb power-reset duration=10s`).
   - Делается до `maxQuickAttempts` попыток (по умолчанию 2 попытки) с интервалом ожидания `quickRetryTicks` (по умолчанию 4 тика = 2 минуты), чтобы модем успел инициализироваться и зарегистрироваться в сети оператора.

3. **Прогрессивный бэкофф (Exponential Backoff):**
   - Если быстрые попытки не восстановили связь (например, авария на базовой станции или долгие техработы оператора), скрипт не спамит перезагрузками модема, а уходит в прогрессивный режим ожидания:
     - **1-й бэкофф-цикл:** пауза **2 часа** (240 тиков по 30 сек).
     - **2-й бэкофф-цикл:** пауза **6 часов** (720 тиков по 30 сек).
     - Последующие циклы удерживают потолок в **6 часов**.

4. **Крайняя мера — перезагрузка роутера:**
   - Если после `maxRebootCycles` полных циклов бэкоффа и быстрых сбросов связь так и не появилась, роутер выполняет полную системную перезагрузку (`/system reboot`). По опыту эксплуатации, иногда зависает стек USB-контроллера на уровне ядра RouterOS, и помогает только полный reboot.

5. **Энергонезависимое сохранение состояния:**
   - Текущий шаг алгоритма, счетчик циклов, оставшееся время ожидания и параметры бэкоффа сохраняются в файл `usb-watchdog-state.txt` на накопителе роутера.
   - Состояние не сбрасывается при случайных перезапусках скрипта или кратковременном отключении питания.

6. **Особенности RouterOS 7.24:**
   - В RouterOS 7 команда `/system routerboard usb power-reset` является блокирующей и возвращает ошибку `reset in progress` при повторном вызове до завершения предыдущего сброса. В скрипте вызов защищен блоком `:do { ... } on-error={ ... }`.
   - Корректная работа с файловой системой через `[find where name~"..."]` и безопасный парсинг без использования устаревших/несовместимых параметров.

7. **Уведомления в Synology Chat:**
   - Оповещение отправляется через Incoming Webhook в Synology Chat **только в момент фактического восстановления связи** после того, как скрипт производил сброс модема или находился в состоянии бэкоффа.
   - В момент аварии уведомления не генерируются, так как при отсутствии интернета доставка невозможна.

## Настраиваемые параметры

В начале файла `usb-watchdog-check.rsc` расположены параметры конфигурации:

| Параметр | Значение по умолчанию | Описание |
| :--- | :--- | :--- |
| `pingAddress` | `"77.88.8.8"` | Контрольный IP-адрес для проверки связи (Яндекс DNS) |
| `failThreshold` | `4` | Количество подряд неудачных проверок для фиксации аварии (4 * 30с = 2 мин) |
| `usbResetDuration` | `"10s"` | Длительность отключения питания USB-порта при сбросе |
| `maxQuickAttempts` | `2` | Количество подряд идущих быстрых попыток USB power-reset |
| `quickRetryTicks` | `4` | Пауза между быстрыми попытками (4 * 30с = 2 мин) для инициализации модема |
| `backoffInitialTicks` | `240` | Длительность первого бэкоффа (240 * 30с = 7200с = 2 часа) |
| `backoffMaxTicks` | `720` | Максимальный потолок бэкоффа (720 * 30с = 21600с = 6 часов) |
| `backoffMultiplier` | `3` | Множитель времени ожидания между циклами бэкоффа (2ч -> 6ч) |
| `maxRebootCycles` | `2` | Количество бэкофф-циклов до выполнения системной перезагрузки роутера |
| `tickSeconds` | `30` | Интервал вызова скрипта планировщиком (в секундах) |
| `webhookUrl` | `https://YOUR-NAS...` | URL входящего вебхука Synology Chat (опционально) |
| `stateFileBase` | `"usb-watchdog-state"` | Базовое имя файла состояния |
| `stateFile` | `"usb-watchdog-state.txt"` | Имя файла состояния на диске роутера |

## Установка и настройка

### Шаг 1. Создание скрипта в RouterOS

#### Вариант А. Через Winbox / WebFig
1. Откройте **System → Scripts**.
2. Нажмите **Add (+)**.
3. Укажите:
   - **Name:** `usb-watchdog-check`
   - **Policy:** отметьте `read`, `write`, `test`, `reboot`, `sniff`, `sensitive`, `ftp`, `policy`
4. В поле **Source** скопируйте и вставьте всё содержимое файла `usb-watchdog-check.rsc`.
5. Нажмите **Apply** → **OK**.

#### Вариант Б. Через терминал MikroTik (импорт или создание)

**Способ 1 (быстрый импорт файла):**
Загрузите файл `usb-watchdog-check.rsc` на роутер и выполните:
```routeros
/system script add name=usb-watchdog-check policy=read,write,test,reboot,policy,sensitive source=[/file get usb-watchdog-check.rsc contents]
```

**Способ 2 (через редактор CLI):**
```routeros
/system script add name=usb-watchdog-check policy=read,write,test,reboot,policy,sensitive
/system script edit usb-watchdog-check source
```
Вставьте код скрипта и нажмите `Ctrl+O` для сохранения и выхода.

---

### Шаг 2. Настройка уведомлений Synology Chat (опционально)

1. В Synology Chat перейдите в **Интеграция** → **Входящие вебхуки** (Incoming Webhooks) → **Создать**.
2. Скопируйте сгенерированный URL вебхука.
3. В скрипте `usb-watchdog-check` найдите строку:
   ```routeros
   :local webhookUrl "https://YOUR-NAS-ADDRESS:5001/webapi/entry.cgi?api=SYNO.Chat.External&method=incoming&version=2&token=YOUR_TOKEN"
   ```
4. Замените URL на ваш реальный вебхук.
5. Если уведомления не требуются, оставьте значение по умолчанию — скрипт пропустит отправку без вывода ошибок в лог.

---

### Шаг 3. Создание задачи в планировщике (Scheduler)

Для автоматического запуска каждые 30 секунд с момента старта роутера выполните в терминале:

```routeros
/system scheduler add name=usb-watchdog-scheduler interval=30s start-time=startup on-event="/system script run usb-watchdog-check" policy=read,write,test,reboot,policy,sensitive
```

## Проверка и диагностика

1. **Просмотр логов работы:**
   ```routeros
   /log print where message~"usb-watchdog"
   ```
   В логах отображаются все события с префиксом `usb-watchdog:`:
   - Количество неудачных пингов (`failCount=...`);
   - Попытки сброса питания USB (`USB power-reset, попытка #...`);
   - Вход в режим ожидания и обратный отсчет тиков (`ожидание, осталось тиков=...`);
   - Вход в бэкофф-циклы;
   - Восстановление связи и отправка вебхуков.

2. **Проверка файла состояния на диске:**
   ```routeros
   /file print where name~"usb-watchdog-state"
   /file get [find where name~"usb-watchdog-state"] contents
   ```
   Формат содержимого: `<попытки_сброса>;<тики_бэкоффа>;<остаток_ожидания>;<циклы_бэкоффа>` (например: `0;240;0;0`).

3. **Ручной тест сброса USB-порта:**
   Убедитесь, что роутер поддерживает управление питанием вашего порта:
   ```routeros
   /system routerboard usb power-reset duration=5s
   ```
